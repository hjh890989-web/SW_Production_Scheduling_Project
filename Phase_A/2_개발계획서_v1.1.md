## 1. 프로젝트 개요

### 1.1 프로젝트명
사내 생산 스케줄링 시스템 (Production Scheduling System, 이하 "본 시스템")

### 1.2 목적
자동차부품 고무호스 제조 공정의 **수주 통합 → 성형·압출 스케줄링 → MES 연동**을 자동화하여, 납기 준수율을 높이고 공정 손실(금형 교체·색상 전환·셋업)을 최소화한다.

### 1.3 도입 배경
- 수주 데이터가 **월별 예상 / KD / 주간 발주** 등 엑셀별로 파편화되어 있어 통합 관리 불가
- 자동차부품 특성상 **다품종·다품번** 구조로 수기 스케줄링 한계
- 성형·압출 공정은 **제약변수가 많아** 사람의 경험에만 의존 시 손실 발생
- 자체 MES 작업실적과의 연동이 부재하여 계획-실적 괴리 발생

### 1.4 도입 전략 — **점진 확대형** (v1.1 명문화)
1. **1차 도입 = '실리콘' 부품군 한정** (약 47품번 규모)
2. 운영 안정화·효과 검증 후 → **EPDM, NBR 등 다른 재료군**으로 확대
3. 시스템은 처음부터 **재료 구분 필드를 포함한 확장 가능 구조**로 설계

### 1.5 도입 가치 (요약)
| 영역 | 기대효과 |
|---|---|
| 납기 | 백워드 스케줄링으로 D-2/D-1 룰 자동 보장 |
| 비용 | 금형 교체·색상 전환·셋업 횟수 최소화 |
| 의사결정 | 수주 변경 시 영향 시뮬레이션 가능 |
| 데이터 | 엑셀 파편화 해소, 단일 통합 DB 확보 |
| 확장성 | 1차 검증 후 타 재료군으로 단계적 확대 |

## 2. 사업 환경 및 문제 인식

### 2.1 사업 환경
- **업종**: 자동차부품 제조 (고무호스)
- **고객**: 자동차 OEM/Tier 공급 (B2B 수주 기반)
- **공정 순서**: 압출(관체 생산) → 성형(가류) → 검사 → 출하

### 2.2 사내 Value Chain 상의 위치
```
[영업·수주]──[자재구매]──[압출]──[성형]──[검사]──[출하]──[사후관리]
     ▲           ▲          ▲       ▲
     │           │          │       │
     └───────────┴──────────┴───────┘
              본 시스템의 영향 구간
              (수주 통합 + 압출/성형 스케줄링 + 실적 연동)
```

### 2.3 문제 정의 (As-Is → To-Be)

| 영역 | As-Is (현재) | To-Be (도입 후) |
|---|---|---|
| 수주 데이터 | 월예상/KD/주간발주 엑셀 3종 파편화, 변동은 메일·전화·새파일이 혼재 | 단일 통합 DB, 변동 직접 입력 GUI, 차이 검증 자동화 |
| 스케줄링 | 수기 작성, 경험 의존 | 자동 백워드 스케줄 + 사용자 수동 보정 |
| 제약변수 | 머릿속에만 존재, 변경 시 대응 어려움 | 명문화·시스템화, 마스터 화면에서 즉시 수정 |
| 실적 연동 | MES 별도 운영, 수기 대조 | 자동 연동, 진척률 실시간 모니터링 |
| 변경 대응 | 수주 변동 시 며칠 소요 | **5분 이내 영향 파악 + 진행중 건 자동 식별** |

> 상세 문제정의서는 Phase A의 산출물로 별도 작성한다.

## 3. 서비스 스코프 및 핵심 비즈니스 룰

### 3.1 1차 도입 범위 (P0 — MVP, **실리콘 한정**)

| # | 모듈 | 핵심 기능 |
|---|---|---|
| 1 | 제품 수주 정보 통합 | 엑셀 3종 업로드, 매핑, 통합 DB, **변동 직접 입력**, 차이 분석 |
| 2 | 성형 공정 스케줄링 | 회전수 기반 자동 + 수동 보정, 가류기·슬롯·앵글 배치 |
| 3 | 압출 공정 스케줄링 | E그룹 기반 자동 + 수동 보정, 신규/포드 부하 분산 |
| 4 | 마스터·캘린더 관리 | 모든 제약조건 GUI 수정 |
| 5 | 재고·목표재고 관리 | 초기 입력, 실적 자동 갱신 |

### 3.2 후속 단계 (P1 / P2)
- **P1**: MES 양방향 연동 (실적 자동수집, 작업지시 송신), 모바일 반응형 조회, 차이 분석
- **P2**: 자동 최적화 엔진 (Google OR-Tools / CP-SAT 솔버), KPI 대시보드, **타 재료군 확대**

### 3.3 핵심 비즈니스 룰 — 백워드 스케줄링

```
                                 ↓ 시간 흐름 →
[압출 시작]──[압출 완료]──[성형 시작]──[성형 완료]──[검사/포장]──[납품]
              D-3 까지        D-3        D-2 까지                  D
              (=성형 투입       │           │                       │
               1일 전)          └─1일 이상──┘                       │
                                            └─────2일 버퍼──────────┘
```

| ID | 룰 | 성격 |
|---|---|---|
| R-1 | 성형 공정은 납품예정일 **D-2까지** 완료 | 하드 제약 |
| R-2 | 압출 공정은 성형 투입일 **D-1까지** 완료 | 하드 제약 |
| R-3 | 모든 스케줄러는 backward scheduling 으로 설계 | 설계 원칙 |
| R-4 | KD 수주에도 D-2/D-1 룰 동일 적용, 트랙은 별도 | 운영 룰 |

### 3.4 수주 통합 우선순위 룰

```
품번 X에 대해:
  ① 주간계획에 있으면     → 주간계획 (Truth, 확정)
  ② 주간계획에 없으면     → KD vs 월예상 중 "더 빠른 납기"를 우선
```

### 3.5 범위 제외 (Out of Scope)
- 검사·포장·출하 공정 스케줄링 (P2 이후 검토)
- 자재 자동 발주 (ERP 영역)
- 원가계산 (ERP 영역)
- 외부망 노출 (사내망 전용)
- **실리콘 외 재료** (P2 이후 확대)

## 5. 시스템 철학 (v1.1 신설)

### 5.1 핵심 원칙 — **"자동배분 → 수동 보정"**
본 시스템은 **완전 자동화를 목표로 하지 않는다**. 모든 자원배분 기능은 다음 2단계로 동작한다.

```
[1] 캘린더·룰 기반 자동배분  →  [2] 생산관리자 수동 미세조정  →  [3] 확정
       (시스템 책임)              (사람 책임 — 경험·판단 흡수)         (운영 반영)
```

### 5.2 원칙의 함의
1. **스케줄러 = 어시스턴트**, 최종 결정권은 사람
2. 모든 자원(가류기·슬롯·앵글·회전수·작업시간 등)은 **드래그·재배분 가능한 UI**로 노출
3. 수동 조정 시 자동 룰 위반은 **경고 표시**, 단 차단하지 않음 (사용자가 알고 결정 가능)
4. **모든 마스터 데이터는 GUI에서 수정 가능** (하드코딩 금지)
5. "자동 추천 vs 사람 확정"은 시각적으로 구분 표시
6. 모든 수정은 **변경 이력**으로 보존

### 5.3 이 원칙이 모든 화면 설계의 기본
- 성형/압출 간트 → 자동 결과 표시 + 드래그 조정
- 마스터 화면 → 수치 즉시 수정
- 수주 통합 → 변동 직접 입력
- 캘린더 → 영업일·PM·휴무 토글

## 7. 모듈별 상세 설계

### 7.1 모듈 1 — 제품 수주 정보 통합

#### 데이터 소스 3종 (실리콘 한정)
| 파일 | 발행 시점·주기 | 확정도 | 식별 방식 |
|---|---|---|---|
| `통합_수주정보_○월_○_○주차.xlsx` | 전월 25일 전후 | 낮음 (월간 forecast) | 파일 전체 (실리콘 호스 전용) |
| `저압 이중관 KD 발주및 납품현황.xlsx` | 수주 발생 시 수시 | 중간 (KD 확정) | **C열 "구분"이 '실리콘'** |
| `실리콘 ○월 ○주차 주간 계획.xlsx` | **전주 목요일** 발행 | 높음 (단, 변동 빈번 — 주 5회) | 파일 전체 (실리콘 전용) |

#### 변동 처리
- 변동 형태: **수량 / 납품일 / 추가품번 / 취소 모두 발생** (특정 빈도 우세 없음)
- 통보 순서: **메일·메신저·전화 (선행) → 파일 재발행/덮어쓰기 (후행)**
- 영향 범위: 이미 압출 시작된 건까지도 가끔 영향 (영향도는 적음)

#### 핵심 기능
1. 엑셀 양식 매핑 등록 (GUI)
2. 자동 검증 (품번 마스터 미존재, 수량 이상치)
3. **변동 직접 입력 GUI** (메일·전화 통보를 즉시 시스템에 반영) — R-7
4. **변경 영향 시뮬레이션** (이미 시작된 압출/성형 건 식별) — R-8
5. 차이 분석 (월예상 vs 주간확정)
6. 이력 관리 (audit trail)

### 7.2 모듈 2 — 성형 공정 스케줄링

#### 장비 구성 (모두 마스터에서 수정 가능)
| 장비 | 대수 | 슬롯 구조 | 회전수 (대당) |
|---|---|---|---|
| 저압가류기 | 4대 | 8슬롯 (상2/중상2/중하2/하2) | 주간 8회 / 야간 10회 |
| IC가류기 | 1대 | 6슬롯 (상2/중2/하2) | 주간 8회 / 야간 10회 |
- 1회전 시간: **약 45분** (40~50, 품번 무관 고정)
- 슬롯당 앵글 1개, 앵글당 금형 N개
- 저압앵글 ↔ IC앵글 호환 불가
- 근무: 월~금 5일, 주야 2교대

#### 핵심 룰
- 한 가류기 안에서 여러 제품 혼재 가능
- **동일 제품을 같은 가류기 여러 슬롯에 셋팅 허용** (회전당 생산량 배수)
- 슬롯 위치 가능여부 O/X = **물리적 불가 (하드 제약)**
- 앵글 교체 시 해당 제품 1회전 손실

#### 알고리즘 단계별 도입
- **1단계 (P0)**: 룰베이스 백워드 + 수동 보정 → 부록 B
- **2단계 (P2)**: OR-Tools / CP-SAT 솔버

#### 출력
- 일자/주야/가류기/슬롯/앵글품번/회전수배분
- **관체 요청서 자동 생성 → 압출 모듈 입력**
- 엑셀 export: 시트명 `*월*일(성형)` + 요약 시트 (이전 docx 형식 호환)

### 7.3 모듈 3 — 압출 공정 스케줄링

#### 장비 및 시간 모델 (모두 마스터에서 수정 가능)
- 압출기 2대: **포드 / 신규**
- 부하 분산 룰: **신규 우선 → 포드 잔여**
- 근무시간:

| 교대 | 전반 | 후반 |
|---|---|---|
| 주간 | 4h | 4h |
| 야간 | 4.5h | 5h |
- 하루 17.5h, **설비 효율 75% (셋업 포함된 평균치)**
- 셋업은 근무시간 시작 전에만 (근무 중 셋업 없음)

#### 셋업 그룹핑
- E열 압출셋팅 1~8 → 같은 숫자끼리 셋업 없이 동시생산
- **헤드/핀이 다르면 같은 E그룹 안에서도 셋업 추가**
- 한 근무시간 안에서 같은 E그룹·헤드핀의 여러 품번 시간 분할 가능

#### 생산량 계산식
```
생산량(EA) = 근무시간(h) × 0.75 × 압출속도(m/min) × 60 ÷ 재단길이(m)
예: 29673-2R060 주간전반 = 4 × 0.75 × 4.5 × 60 / 0.32 ≈ 2,531 EA
```

#### 출력
- 일자/근무/압출기/품번/수량
- 엑셀 export: 시트명 `*월*일(압출)` + 요약 시트

### 7.4 시간 단위 비대칭 (설계 시 주의)
| 공정 | 단위 | 비고 |
|---|---|---|
| 압출 | 시간(h) | 근무시간 분할 |
| 성형 | 회전수(rev) | 1회전 ≈ 45분 |
- 통합 간트 표시 시 **회전수 → 시간 환산** 또는 **두 단위 병행 표시** 적용

## 8. 외부 시스템 연동 (ERP·MES)

### 8.1 자체 MES (양방향)
- API/DB 직접 정의 가능 → 인터페이스 자유 설계
- **읽기**: 작업실적, 라인상태, 재공품 (5분 폴링 또는 webhook)
- **쓰기**: 확정된 작업지시 (현장 태블릿/모니터 표출)
- 인증: 사내망 → API key 또는 IP 화이트리스트

### 8.2 영림원 ERP (단방향)
- **선결 확인사항**:
  1. 표준 API/Web Service 명세서 수령
  2. 직접 DB 조회 가능 여부 (라이선스·지원 계약)
  3. SELECT 전용 DB 계정 발급 가능 여부
- **연동 항목**: 품번마스터, BOM, 거래처, 표준원가
- **갱신 주기**: 1일 1회 야간 배치
- 수주 데이터는 ERP 미경유 (엑셀에서 직접)

### 8.3 통합 데이터 흐름
```
                    [영림원 ERP]
                         │ (1일 1회 야간)
                         ▼
[엑셀 수주]──→ [본 시스템 통합 DB] ←──── [자체 MES]
                         │                  ▲ │
                ┌────────┼────────┐         │ │
                ▼        ▼        ▼         │ │
            [수주통합][성형스케줄][압출스케줄] │ │
                                  │         │ │
                                  └─작업지시─┘ │
                                       작업실적─┘
```

## 부록 B. 스케줄링 알고리즘 의사코드 1차안 (v1.1 신설)

### B.1 마스터 흐름
```
[1단계] 수주 통합  →  실리콘 필터 + 우선순위 룰 적용
[2단계] 성형 스케줄링 (D-2 deadline, 백워드)
[3단계] 관체 요청서 자동 생성
[4단계] 압출 스케줄링 (D-1 deadline, 백워드)
[5단계] 사용자 수동 보정 → 확정
```

### B.2 성형 스케줄러 (룰베이스 P0)
```pseudo
INPUT: 수주(품번X, 납품일D, 수량Q), 재고, 목표재고, 마스터, 캘린더
OUTPUT: S-2 스케줄 + 관체요청서

수주 ← sort by 납품일 asc

FOR each 수주:
  필요수량 ← Q + 목표재고 - 현재고
  회전당산출 ← 앵글당금형수 × 합금형 × (배정슬롯수, default=1)
  필요회전수 ← ceil(필요수량 / 회전당산출)
  
  # 가류기 선택
  IF 저압가능 AND IC가능: 빈슬롯 더 많은 쪽 우선
  ELIF 저압만 가능: 저압
  ELSE: IC
  
  # 슬롯 위치 선택 (O인 위치만, 비어있는 슬롯 우선)
  가능슬롯 ← 위치O이면서 비어있는 슬롯
  IF 가능슬롯 비었으면 → "납기위반 경고"
  
  # 회전 분배 (deadline = D-2일에서 역순으로 채움)
  FOR rev_date FROM (D-2) DOWN TO 오늘:
    IF NOT 영업일(rev_date): continue
    가용회전 ← (주간 8 + 야간 10) × 가류기수 - 이미배정
    배정회전 ← min(가용회전, 필요회전수)
    스케줄.add(rev_date, 가류기, 슬롯, 품번, 배정회전)
    필요회전수 -= 배정회전
    IF 필요회전수 == 0: break
  
  IF 필요회전수 > 0: 알림("D-2 위반 위험: 품번X")

# 관체요청서 자동 생성
관체요청 ← []
FOR each 성형배치:
  관체수량 ← 회전수 × 앵글당금형수 × 합금형
  성형투입일 ← 배정날짜
  관체요청.add(품번, 관체수량, 성형투입일)

RETURN 스케줄, 관체요청
```

### B.3 압출 스케줄러 (룰베이스 P0)
```pseudo
INPUT: 관체요청, 마스터, 캘린더
OUTPUT: S-1 스케줄

# 1) 같은 (E그룹, 헤드/핀)끼리 묶음 (셋업 최소화)
관체요청 ← group by (E그룹, 헤드/핀)
       ← sort by deadline asc within group

FOR each 그룹:
  FOR each 관체요청 in 그룹:
    필요수량 ← 관체수량
    deadline ← 성형투입일 - 1일
    
    # 라인 선택: 신규 우선
    IF 신규가능: 라인 ← 신규
    ELSE: 라인 ← 포드
    
    # 근무시간 슬롯에 백워드 채움
    FOR 근무 IN 가용근무시간 DESC (deadline 이전):
      가능생산 ← 근무시간 × 0.75 × 압출속도 × 60 / 재단길이
      배정 ← min(필요수량, 가능생산)
      스케줄.add(근무, 라인, 품번, 배정)
      필요수량 -= 배정
      IF 필요수량 == 0: break
    
    IF 필요수량 > 0: 알림("D-1 위반 위험: 품번X")

# 2) 부하 균형 후처리
신규부하 ← 신규 가동률
IF 신규부하 > 임계치 AND 포드여유 있음:
  일부 품번을 포드로 재배정 (포드 호환 가능한 것만)

RETURN 스케줄
```

### B.4 변경 영향 시뮬레이션 (R-8)
```pseudo
INPUT: 변경(품번X, 변경유형(수량/일자/추가/취소), 변경값)
OUTPUT: 영향 리스트 + 재계산 결과

영향성형 ← 현 스케줄에서 품번X 배치
영향압출 ← 영향성형의 관체요청

FOR each (성형, 압출) in 영향:
  IF 상태 == "시작" OR "진행중":
    표시 "🔴 진행중 — 현장 확인 필요"
  ELIF 상태 == "확정":
    표시 "🟡 재계산 가능"
  ELSE:
    표시 "🟢 자동 재계산"

재계산결과 ← 위 알고리즘 재실행
변경이력 ← (사용자, 일시, 변경내용, 영향, 사유) 저장

RETURN 영향, 재계산결과
```
