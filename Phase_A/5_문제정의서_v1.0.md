## ⭐ Executive Summary (한 페이지 요약)

### 한 줄 요약
**자동차부품 고무호스 생산의 핵심 병목인 "수주 통합 → 성형·압출 스케줄링"을 사내 웹 시스템으로 자동화하여, 납기 준수와 공정 손실 최소화를 동시에 달성합니다.**

### 문제 (Why now)
- **수주 데이터가 3종 엑셀로 파편화** (월예상·KD·주간계획) → 통합 관리 불가
- **공정 스케줄링은 100% 수기** → 베테랑 1~2인 의존, 야근 발생, 변동 대응 며칠 소요
- **MES 작업실적과 계획이 분리** → 진행률·지연 파악 즉시성 없음
- **수주 변동이 주 평균 5회** 발생 → 진행 중인 압출/성형 건의 영향 추적 불가능

### 솔루션 (What)
- 사내망 전용 **웹 앱**으로 수주 통합 + **백워드 스케줄링**(D-2 성형 / D-1 압출) 자동 + 사용자 수동 보정
- 1차 도입: **'실리콘' 부품군 한정** (약 47품번) → 검증 후 EPDM·NBR 등으로 확대
- 기술 스택: Next.js + Tailwind + Prisma + 사내 PostgreSQL + Docker (Cloud-Ready)

### 기대 효과 (지표 6가지, 현재값은 TBD — 사내 검증 필요)

| 지표 | 현재 (TBD) | 목표 |
|---|---|---|
| 납기 준수율 (D-2/D-1 룰) | TBD% | ≥ 99% |
| 금형/다이스/노즐 변경 손실 횟수 | 월 TBD회 | -30% |
| 수주 변동 → 영향 파악 시간 | 수 시간~며칠 | 5분 이내 |
| 스케줄링 작업시간 | 주 TBD시간 | -50% |
| 데이터 일원화 | 엑셀 3종 분산 | 단일 통합 DB |
| 시스템 채택률 (3개월 후) | - | ≥ 90% |

### 요청사항 (Ask)
1. **본 도입 프로젝트의 임원 승인** (Phase B~D 추진 동의)
2. **예산 배정** (개발 + 인프라, 산정안 별첨 — Phase C 후 확정)
3. **현장 인터뷰 1일 협조** (성형·압출 반장 각 30분)
4. **MES 담당 부서를 정식 stakeholder로 지정**

## 1. 사업 환경 및 시스템 위치

### 1.1 회사 개요
- **업종**: 자동차부품 제조 (고무호스)
- **주요 고객**: 자동차 OEM 및 Tier 1 (B2B 수주 기반)
- **공정**: 압출(관체 생산) → 성형(가류) → 검사 → 출하

### 1.2 사내 Value Chain 상의 본 시스템 위치

```
[영업·수주]──[자재구매]──[압출]──[성형]──[검사]──[출하]──[사후관리]
     ▲           ▲          ▲       ▲
     │           │          │       │
     └───────────┴──────────┴───────┘
              ◀ 본 시스템의 영향 구간 ▶
              (수주 통합 + 압출/성형 스케줄링 + 실적 연동)
```

본 시스템은 **사업의 가장 핵심인 "수주 → 생산"의 연결 고리**를 자동화한다. 이 구간이 막히면 납기·품질·원가 전체가 무너진다.

### 1.3 1차 도입 범위 — 실리콘 부품군 한정
- 실리콘 호스 약 47개 품번 (수주 → 압출 → 성형 → 출하)
- 운영 안정화·효과 검증 후 EPDM, NBR 등으로 점진 확대
- 시스템은 처음부터 **재료 구분 필드를 포함한 확장 가능 구조**로 설계

## 3. As-Is 분석 (현재 어떻게 일하는가)

### 3.1 수주 데이터 — **3종 엑셀로 파편화**

| 데이터 종류 | 발행 시점 | 파일 위치 | 확정도 | 활용 단계 |
|---|---|---|---|---|
| 월간 예상 발주 | M-1월 25일 전후 | `통합_수주정보_*월_*_*주차.xlsx` | 낮음 (예상) | 자재·인력 계획 |
| KD 수주 | 수시 (발생 시) | `저압 이중관 KD ... .xlsx` (8개 시트) | 중간 | 컨테이너 단위 묶음 |
| 주간 확정 | W-1 목요일 | `실리콘 *월 *주차 주간 계획.xlsx` | 높음 (확정) | **실 생산 스케줄링** |

#### 문제점
- 같은 품번의 수주 정보가 **3개 파일에 각기 다른 시점·확정도**로 존재
- KD 파일은 8개 시트(현황·KD현황·kd발주·srm 등)로 **사람만 이해 가능한 가공 시트**
- "어느 것이 truth인가"의 매번 판단이 사람에 의존
- 변경 시 어느 파일을 수정해야 하는지 불명확

### 3.2 공정 스케줄링 — **100% 수기·경험 의존**

#### 성형 공정
- 저압가류기 4대 + IC가류기 1대 (각 슬롯 8개·6개)
- **회전수 기반** 생산 (대당 주간 8회·야간 10회)
- 슬롯 위치 가능 여부, 합금형, 앵글 보유수 등 **제약변수 다수**
- 현재 베테랑이 머릿속으로 모든 변수를 조합하여 스케줄링

#### 압출 공정
- 압출기 2대 (포드, 신규)
- 근무 4교대 (주간 전/후, 야간 전/후), 효율 75%
- E열 압출셋팅(1~8) 그룹 + 헤드/핀 사양 + 다이스/노즐 변경 = **셋업 최소화 퍼즐**
- 현재 사람이 매주 이 퍼즐을 손으로 풀고 있음

#### 문제점
- **베테랑 1~2인 의존 → 휴가·퇴사·인사이동 시 즉시 차질**
- 제약 변수가 **머릿속에만 존재** → 인수인계·교육 어려움
- **D-2(성형) / D-1(압출) 백워드 룰**을 매번 사람이 역산해야 함
- 최적화(금형 교체 최소화·다이스/노즐 변경 묶음)는 시간 부족으로 포기되는 경우 다수

### 3.3 변동 대응 — **주 5회 변동 + 며칠 지연**

| 변동 양상 | 빈도 |
|---|---|
| 수량 변경 | 주 5회 (전체 변동 합산) |
| 납품일 변경 | 동일 |
| 품번 추가 | 동일 |
| 취소 | 동일 |

#### 통보 흐름 (현재)
```
[고객사·영업 변동] 
   ↓ (수 분 ~ 수 시간)
[메일·메신저·전화 1차 통보]
   ↓ (수 시간 ~ 1일)
[파일 재발행 또는 덮어쓰기]
   ↓ (수 시간 ~ 며칠)
[생산관리자가 수기로 일정 재조정]
   ↓
[현장 통보]
```

#### 문제점
- **변동 통보~생산 반영까지 며칠 소요** (특히 진행 중인 건은 추적 어려움)
- 이미 압출 시작된 건이 영향받는지 사람이 일일이 확인
- 변경 이력(누가·언제·무엇을·왜) 추적 불가능 → 사고 시 책임 소재 불명

### 3.4 MES 연동 — **분리 운영**
- 자체개발 MES는 **작업실적·라인상태**를 보유
- 그러나 **수기 스케줄과 별도 운영** → 계획-실적 대조 수기
- 진행률·지연 즉시 파악 불가 → 의사결정 지연

### 3.5 권한·이력 관리 — **부재**
- 엑셀은 누가 언제 변경했는지 추적 곤란
- 영업·생산관리·현장이 같은 파일을 다른 시점에 보고 있음
- 영업비밀(품번·수량·납기·단가) 접근 통제 부재

### 6.2 사용자별 일상 변화

#### 생산관리자 (주 사용자)
- 매일 1회 통합 대시보드로 변동·진행률 확인
- 변동 입력 시 자동 재계산, 사람은 검토·확정
- 주간 회의에서 "수주 변경 시뮬레이션"으로 즉답

#### 현장관리자 (성형/압출)
- 태블릿으로 본인 공정 스케줄·실적 확인
- 작업지시서 자동 출력 → 야간 인수인계 단순화

#### 영업·구매
- 수주 엑셀 업로드 → 자동 검증·분류

- 데이터 기반 의사결정

## 7. Gap (격차 — 채워야 할 것들)

### 7.1 데이터 격차
- 통합 DB 인프라 부재 → **PostgreSQL + Prisma 기반 통합 DB 구축**
- 마스터 데이터(품번·BOM) 단일화 필요 → **영림원 ERP 연동**
- 변경 이력·실적 통합 필요 → **자체 MES 양방향 연동**

### 7.2 알고리즘 격차
- 백워드 스케줄링 자동화 부재 → **룰베이스 + (P2) OR-Tools 솔버**
- 변경 영향 시뮬레이션 부재 → **차이 분석 + 진행중 건 식별 로직**

### 7.3 UI·UX 격차
- 간트차트 기반 시각화 부재 → **간트 라이브러리 도입** (Bryntum/DHTMLX)
- 수동 보정 인터페이스 부재 → **드래그·재배분 가능한 화면**
- 모바일 조회 부재 → **반응형 웹 (PWA)**

### 7.4 운영·보안 격차
- 인증·권한 관리 부재 → **로그인 + RBAC** (1차 자체 ID/PW, 2차 AD/LDAP)
- 변경 이력 부재 → **Audit 로그 (모든 변경에 사용자 ID·일시·내용)**
- 백업·재해복구 부재 → **일일 백업 + 사내 NAS**

### 7.5 인적 격차
- 베테랑 노하우의 시스템화 → **제약변수 명문화 + 마스터 데이터 GUI**
- 신규 사용자 교육 → **PRD·와이어프레임 단계에서 현장 검증 인터뷰 1일**

## 8. 도입의 당위성

### 8.1 정량 효과 (KSF 달성 시)
- 납기 준수율 ≥ 99% → OEM 신뢰도 유지·확대 수주 가능성
- 금형/다이스/노즐 변경 -30% → 직접적 원가 절감
- 변동 영향 파악 5분 이내 → 의사결정 속도 ↑
- 스케줄링 작업시간 -50% → 인건비 절감 + 베테랑의 고부가 업무 전환

### 8.2 정성 효과
- **베테랑 의존 리스크 해소** — 노하우의 시스템화로 인사이동에도 안정 운영
- **데이터 기반 경영** — KSF 6지표 실시간 모니터링으로 의사결정 정확도 ↑
- **확장 기반** — 실리콘 검증 후 EPDM·NBR·타 공장으로 동일 시스템 확대

### 8.3 전략 효과
- **자동차부품 산업의 디지털 전환 흐름 동참** — OEM의 디지털 공급망 요구 대응
- **미래 클라우드 이전 가능성 확보** — Cloud-Ready 12-Factor 설계로 사내→클라우드/SaaS화 옵션 보존
- **신규 사업 기반** — 향후 동종 업계에 SaaS 형태 판매 검토 가능 (P2 이후)

### 8.4 리스크 (대응책 포함)
| 리스크 | 영향 | 대응 |
|---|---|---|
| 영림원 ERP 직접 연동 불가 | 마스터 동기화 차질 | 표준 API 우선, 안 되면 야간 엑셀 export |
| 현장 반장의 시스템 거부 | 도입 실패 | Phase B 인터뷰로 사전 흡수 + **수동 조정 UI**로 자율성 보장 |
| 외주 견적 편차 | 예산 초과 | PRD + 와이어프레임 완비 후 발주 |
| 미래 클라우드 이전 시 ERP/MES 종속성 | 이전 비용 증가 | **Cloud-Ready 사전 적용** (이전 비용 90% 절감) |

> 전체 리스크 R1~R9는 개발계획서 v1.3 14장 참조.

## 9. 1차 도입 범위 (재확인)

### 9.1 P0 (MVP)
1. 제품 수주 정보 통합 (엑셀 3종 → 단일 DB)
2. 성형 공정 스케줄링 (룰베이스 백워드)
3. 압출 공정 스케줄링 (E그룹·신규우선)
4. 마스터·캘린더 관리 (모든 제약 GUI 수정)
5. 재고·목표재고 관리

### 9.2 후속 단계
- **P1**: MES 양방향 연동, 모바일 반응형
- **P2**: OR-Tools 자동 최적화, AD/LDAP SSO, 타 재료군(EPDM·NBR) 확대

### 9.3 기술 스택 (요약, 상세는 개발계획서 13장)
- Next.js + Tailwind + shadcn/ui + Prisma + 사내 PostgreSQL + Docker (Cloud-Ready)
- **사용 금지**: Vercel, Supabase, 외부 LLM API (사내망 정책 D8)

### 9.4 일정
- Phase B (사용자·가치): 1주
- Phase C (PRD + 와이어프레임): 3~4주
- Phase D (단계별 MVP): 6~9개월
- 총 기획기간 6~8주 + 개발 6~9개월
