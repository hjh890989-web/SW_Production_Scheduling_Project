# 대화기록 — Check In 브랜드 전략 수립
**일자**: 2026-05-12
**주제**: 송우산업 사내 자동화 서비스 통합 브랜드(BI) "Check In" 정립
**범위**: FCB(유류비 청구) + EVS(성형·압출 스케줄링) + 향후 확장 예정 서비스 전체

---

## 📌 전체 요약

송우산업의 사내 업무 자동화 서비스가 늘어남에 따라, 통합 브랜드 우산(Brand Architecture)을 일찍 도입하는 전략을 수립함. 모(母) 브랜드 **"Check In (체크인)"** 아래 서비스 약어를 결합하는 패턴(`체크인 - FCB`, `체크인 - EVS` 등)을 채택. 3중 의미(보고·확인·시작)를 정의하고, 공식 슬로건과 시각 아이덴티티 가이드 v1.0을 확정. 회장 보고용 BI 정당성 슬라이드와 Figma 입력용 로고 생성 프롬프트까지 도출.

## 1️⃣ 두 프로젝트 사전 분석

대화 시작 시 사용자 요청: 두 프로젝트의 내용을 파악할 수 있는지 확인.

### Fuel-Cost-Automatic-Billing-Project (FCB)
- **상태**: 가동 중인 실 코드베이스
- **도메인**: 송우산업 직원 자차 운행 유류비 자동 청구·결재 시스템
- **스택**: Flask 3 + SQLAlchemy + Jinja2 + SQLite, waitress, APScheduler
- **외부 연동**: 한국석유공사 오피넷 API(유가), 네이버 지도 API(거리)
- **핵심 로직**: `유류비 = (거리 ÷ 공인연비 × 0.7 효율계수) × 유가단가`
- **결재 워크플로우**: 금액별 분기 (≤10만원: 팀장 / >10만원: 팀장+임원), 이후 경영기획팀 검수→검토→승인
- **DB 모델**: 9개 테이블 (User, Vehicle, Destination, Distance, FuelPrice, Claim, ClaimItem, Approval, Attachment)

### SW_Production_Scheduling_Project (EVS)
- **상태**: 설계·명세 단계 (코드 없음, Phase D에서 115 Task 명세 완성)
- **도메인**: 자동차부품 고무호스 제조 공정(성형·압출) 스케줄링 자동화
- **1차 범위**: 실리콘 47품번 (검증 후 EPDM·NBR 확장)
- **계획 스택**: Next.js 14 + TS + Prisma + PostgreSQL 15 + Auth.js v5 + Docker (사내망 전용, 클라우드 SaaS 금지)
- **KSF**: 납기 준수율 ≥99%, 금형·다이스 교체 -30%, 변동 영향 분석 ≤5분
- **Sprint 구성**: S0~S11 = Must (~12주), S12(LLM·모바일) = P2

### 두 프로젝트의 결정적 차이
- FCB: 운영 중인 실 코드베이스
- EVS: 115개 Task 명세까지만 작성된 설계 단계

## 2️⃣ 브랜딩 아이디어 제안 (사용자)

> "이 2가지의 프로젝트는 내가 재직 중인 회사 내부에서 사용할 프로젝트들이야. 지금은 2개의 프로젝트이지만, 이런식으로 업무 자동화 방향으로 유사 프로젝트 적용 범위를 넓힐 계획이야. 그래서 나는 이렇게 회사 내부에 제공하는 서비스를 브랜드화하고 싶어. '브랜드 네임 + 서비스 네임' 식으로 BI를 하고 싶어.
>
> 예를 들어 'Cheek In - EVS(Extrusion & Vulcanization Scheduling)', 'Cheek In - FCB(Fuel Cost Billing)', 'Cheek In - ALM(Attendance and leave management) 등을 의미하는 것이야."

### Claude 피드백
- **패턴 자체는 매우 강력함** — Microsoft 365, Atlassian, Google Workspace 등 글로벌 표준
- **'Cheek In' 오기 가능성 지적**: 'cheek'는 '뺨/볼'을 의미해서 비즈니스 브랜드에 부적절
- 트레이드오프 3가지: 확장성, 한국어 발음·표기, 약어 충돌(ALM = IT 표준 Application Lifecycle Management)

## 3️⃣ Check In 의미 정의 및 한국어 병기 (사용자)

사용자 정정:
- 'Check In'의 오기 맞음
- 의도: "여기를 통해서 업무에 돌입한다"
- 한국어 병기 예정: "체크인 - FCB(유류비 청구)"

### Claude 추가 점검 사항 4가지
1. **서비스 약어 명명 규칙**: 3글자 고정 / 도메인 두문자 조합 규칙화
2. **URL/네트워크 구조**: 서브패스 vs 서브도메인 (SSO 도입 시 결정 비용 큼)
3. **시각 아이덴티티**: 모 브랜드 컬러 + 서비스별 액센트 컬러 패턴
4. **통합 로그인(SSO)**: EVS의 Auth.js를 Check In SSO 기준점으로 설계 권장

코드/리포 명명 규칙: `checkin-fcb`, `checkin-evs` 식.

### 정합도 매트릭스
| 회사 정체성 요소 | Check In 브랜드와의 정합도 | 평가 |
|---|---|---|
| 일터혁신대상 최우수기업 | 친근·직관적 디지털 진입점 컨셉과 정합 | ✅ 매우 좋음 |
| 야근·회식 강요 X, 자유복장 | 캐주얼한 IT 톤이 대외 이미지와 일치 | ✅ 좋음 |
| 직원 평균 연령(현장 반장 45~49세) | 호텔 체크인 메타포는 전 연령 친숙 | ✅ 무난 |
| B2B 제조업 (현대·기아·르노 협력사) | 사내 한정 브랜드이므로 무관 | ⚪ 중립 |
| 박수곤 회장(60대) 의사결정자 | "체크인"의 IT 의미 익숙도 낮을 수 있음 | ⚠️ 검토 필요 |
| "고무호스 국산화·선진화" 산업 정체성 | Check In은 가벼운 톤 | ⚠️ 검토 필요 |

### 마찰점 2가지 + 해결책 제안
1. **FCB와 컨셉 일관성 약함**: 유류비는 사후 처리이지 업무 진입점이 아님 → "사내 모든 업무 시스템의 단일 게이트웨이"로 컨셉 확장 권장
2. **회장 세대 브랜드 정당성 설명**: 호텔 체크인 연상 압도적 → 한 줄 브랜드 라인 준비 ("체크인 — 모든 업무는 여기서 시작됩니다" 등)

## 6️⃣ 3중 의미 확장 (사용자가 정립한 핵심 통찰)

> "'Check in'은 단순히 출석 체크의 의미를 넘어, 다음과 같은 다중적인 메시지를 줄 수 있습니다.
>
> - **Status Check**: '현재 우리 공정/비용의 상태가 어떤가?' (EVS, FCB 등 데이터 현황 파악)
> - **Validation**: '이 수치가 맞는가?' (자동 계산 및 검증을 통한 휴먼 에러 방지)
> - **Process Start**: '업무를 시작하기 전 거쳐야 할 필수 관문' (표준화된 시스템 활용)"

### Claude 평가
이 3중 의미 확장으로 이전에 제기된 두 마찰점이 정확히 해소됨:
- **FCB 정합성 약함 → 해결**: "Status Check + Validation"이 청구·검증 flow를 정면으로 포괄
- **회장 세대 설명 → 해결**: "필수 관문(standardized gateway)" 표현이 임원 톤에 적합

### 3중 의미와 송우산업 페인포인트 매핑
| Check In 레이어 | 송우산업 As-Is 페인포인트 |
|---|---|
| **Status Check** | "변동 영향 파악에 수 시간~며칠 소요" / 결재 현황 가시성 부족 |
| **Validation** | "베테랑 1~2인 의존, 수기 → 휴먼 에러" / 일터혁신 우수기업 정체성과 직결 |
| **Process Start** | "수주 엑셀 3종 파편화" / KSF-5 "데이터 일원화 100%" |

→ 세 의미 모두가 **"능동적·지능적 사내 업무 게이트웨이"** 로 브랜드를 위치시킴.

## 7️⃣ 공식 슬로건 확정 — A안

### 최종 결정
> # 체크인 — 보고, 확인하고, 시작하다
> ### Check In — See it. Verify it. Start it.

### 결정 근거
- 3중 의미 1:1 매핑 (보고=Status Check, 확인=Validation, 시작=Process Start)
- 한국어 3음절×3 운율 → 기억성·구전성 우수
- 동사형 능동 구조 → "능동적으로 굴러간다"는 인상
- 사용 범위: 현장 반장(박철수)부터 회장(박수곤)까지 발화 자연스러움
- 도메인 확장 시에도 의미 견고 (ALM·BI·품질 어떤 도메인 추가돼도)

### 비교 후보
- B: "체크인 — 송우의 모든 업무가 거치는 단 하나의 관문" (Process Start 강조)
- C: "체크인 — 데이터는 확인되고, 일은 시작된다" (Validation 강조)

## 8️⃣ 회장 보고용 BI 정당성 슬라이드 (1장)

```
═══════════════════════════════════════════════════════════════
                                                     [송우산업㈜]
                                                  사내 시스템 통합 BI

                         Check In 도입(안)
            ── 송우의 모든 일이 거치는 단 하나의 관문 ──

       "체크인 — 보고, 확인하고, 시작하다"
═══════════════════════════════════════════════════════════════
```

### ① 왜 지금, 브랜드인가
- 사내 자동화 시스템 **2종 운영 중** (FCB, EVS), 향후 **5~10종 추가 도입 예정**
- 문제: 시스템마다 별도 이름·로고·로그인 → 직원 학습 부담, 인지도 분산
- 해법: **단일 모(母) 브랜드 우산(Brand Architecture)**

### ② 왜 'Check In'인가 — 3중 의미가 송우 현장 과제와 일치
1. **보고 (Status Check)**: EVS 변동 영향 5분 내 파악 / FCB 결재 현황 즉시 조회
2. **확인 (Validation)**: 자동 계산·검증으로 휴먼 에러 차단 (일터혁신·인간존중생산성 우수기업 정체성)
3. **시작 (Process Start)**: 베테랑 1~2인 의존·수기 → 표준 게이트웨이 전환

### ③ 글로벌 검증된 패턴
- Microsoft 365 (Word·Excel·Teams)
- Atlassian (Jira·Confluence·Bitbucket)
- Google Workspace (Gmail·Drive·Meet)
→ 직원 200명 중견기업에서도 충분히 검증된 접근

### ④ 적용 사례
- **체크인 - FCB** (Fuel Cost Billing, 유류비 청구)
- **체크인 - EVS** (Extrusion & Vulcanization Scheduling)
- **체크인 - ALM** (Attendance & Leave Management, 향후)

### ⑤ 기대 효과
- 직원: 일관된 UX·로그인 (학습 부담 ↓)
- 회사: 디지털 전환 추진 28년차 중견 제조사 정체성 강화
- 인프라: 향후 통합 로그인(SSO) 기반 마련
- 외부 평판: 채용·홍보·산학협력 시 "디지털 전환 선도 제조기업" 메시지 활용

### ⑥ 추진 로드맵
1. EVS·FCB에 브랜드 적용 (개발 중, **추가 비용 없음**)
2. 로고·컬러 가이드 1페이지 확정
3. 신규 시스템(ALM 등)부터 브랜드 일관 적용
4. SSO 통합 인증으로 단일 로그인 완성

> 요청 사항: 'Check In' 브랜드 도입 승인 — 추가 예산 소요 없음, 현재 진행 중인 EVS·FCB 개발에 즉시 적용 가능
