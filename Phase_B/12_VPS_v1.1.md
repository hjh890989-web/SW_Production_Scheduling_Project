# ⭐ Executive Summary (임원 1페이지)

## 한 줄 가치 제안
> **"베테랑이 며칠 걸려도 다 풀지 못하던 스케줄링 퍼즐을, 시스템이 5초 안에 초안을 만들고 베테랑은 검토·수정만 하는 구조."**

## 3가지 핵심 메시지
1. **납기를 지키며 손실은 줄인다** — 납기율 93→99%, 다이/노즐+금형 변경 -30%, 변동 영향 4시간→5분 (-98%)
2. **베테랑 의존을 시스템 의존으로** — 25년 노하우 명문화, 휴가·이직 차질 해소
3. **사람의 시간을 고부가 업무로** — 주 24h→12h, 연간 ≈ 1,000시간 = 정규직 0.5명 분량

## 한 줄 결론
> **"베테랑의 시간을 살리고, 납기를 지키며, 손실을 줄이고, 미래 확장을 위한 데이터 자산을 쌓는다. 회수 18개월 이내, 위험 통제 가능. 즉시 진행 권고."**

> 상세 검토는 1~10장. 임원 결재는 10장 참조.

# 2. 페르소나 JTBD 선언문

JTBD 표준 양식: **"[상황]일 때, [동기]하기 위해, [기대 결과]를 얻고 싶다"**

## 2.1 김민수 과장 (생산관리) — 4건

> **J-PM-1 ⭐** "수주 변동이 발생했을 때, 진행 중인 압출/성형 건이 영향받는지 즉시 파악하기 위해, **5분 안에 영향 시뮬레이션 결과를 시각화**하고 싶다."

> **J-PM-2 ⭐** "OEM 납품일이 다가올 때, D-2/D-1 룰을 위반하지 않기 위해, **시스템이 자동으로 백워드 스케줄을 생성하되 내가 최종 수동 조정**하고 싶다."

> **J-PM-3** "휴가·인수인계 시점에, 후임이 당황하지 않도록, **모든 제약변수와 변경 이력이 시스템에 명문화**되어 있기를 원한다."

> **J-PM-4** "설비 고장·자재 부족·인원 부족(연차) 등 자원 이상이 발생했을 때, 영향받는 건을 빠르게 식별하고 재계획하기 위해, **자원 이상 시뮬레이션** 기능을 사용하고 싶다."

## 2.2 박철수 반장 (성형) — 3건

> **J-MR-1 ⭐** "새벽 교대 직후 오늘 무엇을 만들지 빠르게 파악하기 위해, **태블릿 한 화면에 본인 가류기의 일정**(슬롯·앵글·회전수)이 정리되어 있기를 원한다."

> **J-MR-2 ⭐⭐** "자동 스케줄이 현장 직관과 어긋날 때, 시스템이 강제하지 않고 **내 수동 보정을 받아주고 경고만 표시**해주기를 원한다." **← 도입 성패 결정 JTBD**

> **J-MR-3 ⭐** "슬롯 위치 제약이 많아 한 번에 계산할 수 없는 상황에서, **시스템이 5초 안에 초안을 제시**하고 내가 검토·수정하기를 원한다."

## 2.3 이영호 반장 (압출) — 3건

> **J-ER-1 ⭐** "다이/노즐 변경 횟수를 줄이기 위해, 시스템이 **같은 E그룹·헤드핀의 품번들을 한 근무시간에 묶어 배치**해주기를 원한다."

> **J-ER-2** "납기 위반을 피하면서도 셋업을 최소화하기 위해, **자동 일정 + 내 수동 미세조정**이 모두 가능하기를 원한다."

> **J-ER-3** "신규/포드 가동률을 균형 있게 유지하기 위해, **시스템이 부하 분산을 자동 계산하되 결과를 시각적으로** 보여주기를 원한다."

## 2.4 정수진 대리 (영업·구매) — 2건

> **J-SP-1 ⭐** "OEM이 다양한 채널(엑셀·메일·전화·카톡)로 보내온 발주를 사내에 통합 전달하기 위해, **한 번 입력하면 시스템이 자동 통합·매핑**해주기를 원한다."

> **J-SP-2** "변동 발생 시 책임 소재를 명확히 하기 위해, **내가 입력한 변동이 시스템에 audit 기록**되고 생산팀에 즉시 알림이 가기를 원한다."

## 2.5 경영진 (이사) — 2건

> **J-EX-1** "이사회·OEM 미팅 시 KSF 6지표를 즉시 보여주기 위해, **모바일에서도 대시보드가 한 화면**에 정리되기를 원한다."

> **J-EX-2** "본 시스템 도입의 ROI를 입증하기 위해, **도입 전후 KSF 변화 추이가 자동 비교**되기를 원한다."

→ 총 **14건 JTBD**. 상세는 #10 JTBD 리스트 참조.

# 4. 공통 설계 원칙 (안전 및 규제 프로토콜)

본 시스템 전체에 적용되는 횡단 원칙. **모든 모듈·화면·데이터 흐름에 일관 적용**.

## 4.1 시스템 철학 (D10) — 자동배분 → 수동 보정
- 모든 스케줄링·자원배분은 2단계: ① 자동 초안 → ② 사람 검토·확정
- 시스템은 어시스턴트, **최종 결정권은 사람**
- 자동 룰 위반 시 **차단 X, 경고 표시만**
- 자동 결과와 사람 확정을 시각적으로 구분

## 4.2 인증·권한 (D18, R-13)
- **전 사용자 로그인 필수** (사내망이라도 audit 위해)
- **RBAC** — 페르소나 5종 + Admin = 6 Role
- **모든 변경에 사용자 ID 자동 기록** (audit 로그)
- 1차: 자체 ID/PW (Auth.js, bcrypt) / 2차: AD/LDAP SSO
- 비밀번호 정책·세션 만료 사내 표준 준수

## 4.3 데이터 주권·영업비밀 보호 (D8)
- **사내망 전용 배포** — 외부 노출 없음
- **OEM 영업비밀**(품번·수량·납기·단가)이 **외부 클라우드로 전송되지 않음**
- 사용 금지: Vercel, Supabase, Google Gemini API, OpenAI API
- IP 화이트리스트 + HTTPS (사내 인증서)

## 4.4 Cloud-Ready (D20, 12-Factor)
- 모든 설정 환경변수
- Docker 컨테이너화
- 무상태 앱 (세션은 외부 저장소)
- 객체 스토리지·DB·인증·MES·ERP 모두 인터페이스 추상화
- 미래 클라우드 이전 시 마이그레이션 비용 90% 절감

## 4.5 자동차부품 OEM 컴플라이언스 (추적성)
- **Audit 로그 5년 보존** (자동차부품 추적 표준 부합)
- 변경 이력 = (사용자·일시·내용·이전값·신규값·사유·IP·세션)
- 백업: 일일 → 사내 NAS, 1년 보존
- 시스템 다운 시 즉시 알림 + 수기 백업 절차

## 4.6 데이터 무결성 룰
- D-2 / D-1 백워드 스케줄링은 **하드 제약** (R-1, R-2, R-3) — 룰 변경 불가
- 통합 우선순위 룰: 주간계획 ▶ KD/월예상 빠른 납기 (R-5)
- 실리콘 1차 한정 → 향후 확대 시에도 재료 구분 필드 유지 (R-6)

## 4.7 UX 원칙 (페르소나 분석 기반)
- **베테랑 친화** (박·이 반장): 큰 글씨·단순 메뉴·명확한 색상 코딩
- **자동 vs 수동 시각 구분**
- **본인 공정만 보이는 필터** (RBAC 연계)
- **데스크탑 + 태블릿 반응형** (현장 태블릿 최적화)
- 변경 시 항상 "왜 이 결과가 나왔는지" 근거 표시 (블랙박스 X)

## 4.8 신뢰성·가용성
- 단일 서버 + 일일 백업 (1단계 — 20명 규모)
- 시스템 다운 시 수기 절차 가능 (엑셀 export 백업)
- 정기 점검: 월 1회 (사내 IT)
