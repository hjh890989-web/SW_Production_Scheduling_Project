## 1. JTBD 표준 양식

본 문서의 모든 JTBD는 다음 표준 양식을 따른다.

> **"[상황]일 때, [동기]하기 위해, [기대 결과]를 얻고 싶다"**

영문 원형 (Clayton Christensen 양식):
> **"When [situation], I want to [motivation], so I can [outcome]."**

각 JTBD에 다음 속성을 부여:
- **Job Code**: J-페르소나약자-순번 (예: J-PM-1)
- **우선순위**: P0 (MVP 필수) / P1 (안정화 단계) / P2 (확장)
- **Big/Small**: Big (전략적 핵심) / Small (세부 기능)
- **연관 R**: 관련 요구사항 ID
- **연관 F**: 관련 기능 ID
- **연관 KSF**: 측정 KSF

## 7. 핵심 통찰 (PRD 작성 시 우선순위 가이드)

### 7.1 JTBD에서 도출된 PRD 우선순위 5가지
1. **R-11 (자동→수동 보정)** = 3개 JTBD가 직접 지목 → **모든 스케줄링 화면의 최우선 UX 원칙**
2. **R-7 (변동 입력) + 확장** = 수주 + 변동 통합 GUI는 P0의 1순위 화면
3. **R-8 (영향 시뮬) + 확장** = 변동 + 자원 이상 모두 시뮬 가능해야 함
4. **R-13 (인증·권한)** = audit 로그가 페르소나 4·5의 핵심 가치 (책임·OEM 신뢰)
5. **R-9 (마스터 GUI)** = 3개 페르소나(박·이·생관)의 핵심 욕구

### 7.2 채택률(KSF-6)을 위한 핵심 JTBD = J-MR-2
> "자동 스케줄이 현장 직관과 어긋날 때, 시스템이 강제하지 않고 내 수동 보정을 받아주기를 원한다"

이 한 가지를 어기면 **박철수 반장이 시스템을 거부 → MVP-2 도입 실패**. 다른 모든 JTBD를 충족해도 무용.

→ Phase C PRD·와이어프레임 단계에서 **이 JTBD를 가장 먼저 시각적으로 검증**.

### 7.3 임원 보고용 한 줄 메시지 (B-5 VPS의 핵심)
> **"베테랑이 며칠 걸려도 다 풀지 못하던 스케줄링 퍼즐을, 시스템이 5초 안에 초안을 만들고 베테랑은 검토·수정만 하는 구조"**
