# ⭐ Executive Summary (임원 1페이지)

## 한 줄 가치 제안 (Value Proposition)
> **"베테랑이 며칠 걸려도 다 풀지 못하던 스케줄링 퍼즐을, 시스템이 5초 안에 초안을 만들고 베테랑은 검토·수정만 하는 구조."**

→ **Pain → Mechanism → Outcome** 구조: (며칠 걸려도 못 푸는 퍼즐) → (5초 자동 초안) → (검토·수정만으로 운영)

## 3가지 핵심 메시지
1. **납기를 지키며 손실은 줄인다** — 납기율 93→99%, 다이/노즐+금형 변경 -30%, 변동 영향 4h→5분 (**-98% / 약 48배**)
2. **베테랑 의존을 시스템 의존으로** — 25년 노하우 명문화, 휴가·이직 차질 해소
3. **사람의 시간을 고부가 업무로** — 주 24h→12h, 연간 ≈ 1,000시간 = **정규직 0.5명 분량**

## 한 줄 결론
> **"베테랑의 시간을 살리고, 납기를 지키며, 손실을 줄이고, 미래 확장을 위한 데이터 자산을 쌓는다. 회수 18개월 이내, 위험 통제 가능. 즉시 진행 권고."**

> 상세 검토는 1~12장. 임원 결재는 12장 참조. 근거 데이터는 부록 참조.

# 2. JTBD 선언문 (When / I want to / So I can + Desired Outcome)

표준 양식: **"When [상황], I want to [동기], so I can [기대 사업 가치]"**, **Desired Outcome은 정량 지표**로 분리.

## 2.1 김민수 과장 (생산관리) — 4건

### J-PM-1 ⭐
- **When**: 수주 변동(수량/일자/추가/취소)이 발생했을 때
- **I want to**: 진행 중인 압출·성형 건의 영향을 5분 안에 시각화하여 검토하고 싶다
- **So I can**: OEM 납기 사고를 사전 차단하고, 주간 회의에서 즉답할 수 있다
- **Desired Outcome**: 영향 파악 시간 **4h → 5분 (-98%, 약 48배 단축)**

### J-PM-2 ⭐
- **When**: OEM 납품일이 다가올 때
- **I want to**: 시스템이 자동으로 D-2/D-1 백워드 스케줄을 생성하되 내가 최종 수동 조정하고 싶다
- **So I can**: 베테랑 직관과 자동 알고리즘의 장점을 결합하여 납기를 100% 지킬 수 있다
- **Desired Outcome**: 납기 준수율 **93% → ≥ 99%**, 스케줄링 작업시간 **주 4h → 2h (-50%)**

### J-PM-3
- **When**: 휴가·인사이동·인수인계 시점에
- **I want to**: 모든 제약변수와 변경 이력이 시스템에 명문화되어 있기를 원한다
- **So I can**: 후임이 즉시 운영을 인수하고 사고 없이 업무가 이어진다
- **Desired Outcome**: 위임 가능 후임 **0명 → 1명+**, 인수인계 사고 **0회/년**

### J-PM-4 🆕
- **When**: 설비 고장·자재 부족·인원 부족(연차) 등 자원 이상이 발생했을 때
- **I want to**: 영향받는 건을 빠르게 식별하고 자원 이상 시뮬레이션을 사용하고 싶다
- **So I can**: 1~2시간 걸리던 재계획을 5분에 끝내고 야근을 줄일 수 있다
- **Desired Outcome**: 자원 이상 대응 시간 **1~2h → 5분**, 변동 대응 야근 시간 **-50%**

## 2.2 박철수 반장 (성형) — 3건

### J-MR-1 ⭐
- **When**: 새벽 교대 직후
- **I want to**: 태블릿 한 화면에 본인 가류기의 일정(슬롯·앵글·회전수)이 정리되어 있기를 원한다
- **So I can**: 종이·카톡을 거치지 않고 즉시 작업 시작할 수 있다
- **Desired Outcome**: 일정 확인 시간 **30분 → 1분**, 종이 인쇄 **-100%**

### J-MR-2 ⭐⭐ (도입 성패 결정 JTBD)
- **When**: 자동 스케줄이 25년 경험상의 직관과 어긋날 때
- **I want to**: 시스템이 강제하지 않고 내 수동 보정을 받아주고 경고만 표시해주기를 원한다
- **So I can**: 시스템을 신뢰하면서도 내 판단의 자율성을 유지할 수 있다
- **Desired Outcome**: **시스템 채택률 ≥ 90%** (KSF-6), 박철수 페르소나 만족도 ≥ 4/5

### J-MR-3 ⭐
- **When**: 슬롯 위치 제약이 많아 머리로 한 번에 계산할 수 없는 상황에서
- **I want to**: 시스템이 5초 안에 초안을 제시하고 내가 검토·수정하기를 원한다
- **So I can**: 내 결정시간 0.5~1시간을 절약하고 가동을 빨리 시작할 수 있다
- **Desired Outcome**: 결정 시간 **0.5~1h → 5초 + 검토 5분**, 다이/노즐+금형 변경 **-30%**

## 2.3 이영호 반장 (압출) — 3건

### J-ER-1 ⭐
- **When**: 일일 작업 일정 받았을 때
- **I want to**: 시스템이 같은 E그룹·헤드핀의 품번들을 한 근무시간에 묶어 배치해주기를 원한다
- **So I can**: 다이/노즐 변경 횟수를 줄이고 라인 가동률을 높일 수 있다
- **Desired Outcome**: 다이/노즐 변경 **일 5~10회 → 일 3.5~7회 (-30%)**, 라인 비가동 시간 **월 55~110h → 월 38~77h**

### J-ER-2
- **When**: 자동 일정만으로 부족하거나 현장 상황이 다를 때
- **I want to**: 자동 일정 + 내 수동 미세조정이 모두 가능하기를 원한다
- **So I can**: 셋업을 최소화하면서도 D-1 납기를 위반하지 않을 수 있다
- **Desired Outcome**: 압출 D-1 준수율 **현재 (TBD) → ≥ 99%**

### J-ER-3
- **When**: 신규/포드 두 라인을 동시 운영할 때
- **I want to**: 시스템이 부하 분산을 자동 계산하고 결과를 시각적으로 보여주기를 원한다
- **So I can**: 한 라인 과부하 없이 두 라인을 균형 있게 가동할 수 있다
- **Desired Outcome**: 가동률 차이 **(TBD) → ≤ 10%**

# 4. 공통 설계 원칙 (안전 및 규제 프로토콜)

## 4.1 시스템 철학 (D10) — 자동배분 → 수동 보정
모든 스케줄링은 ① 자동 초안 → ② 사람 검토·확정. 시스템은 어시스턴트, 최종 결정권은 사람. 룰 위반 시 차단 X, 경고만.

## 4.2 인증·권한 (D18, R-13)
전 사용자 로그인 필수, RBAC(6 Role), 모든 변경에 사용자 ID 자동 기록. 1차 자체 ID/PW → 2차 AD/LDAP SSO.

## 4.3 데이터 주권·영업비밀 보호 (D8)
사내망 전용 배포. OEM 영업비밀(품번·수량·납기·단가)이 외부 클라우드로 전송되지 않음. **사용 금지: Vercel, Supabase, Google Gemini API, OpenAI API**.

## 4.4 Cloud-Ready (D20, 12-Factor)
환경변수 외부화, 컨테이너화, 무상태 앱, 모든 백킹 서비스 추상화. 미래 클라우드 이전 비용 90% 절감.

## 4.5 자동차부품 OEM 컴플라이언스 (추적성)
Audit 로그 5년 보존, 변경 이력 = (사용자·일시·내용·이전값·신규값·사유·IP·세션). 백업: 일일 → 사내 NAS, 1년 보존.

## 4.6 데이터 무결성 룰
D-2/D-1 백워드 = 하드 제약 (R-1·R-2·R-3). 통합 우선순위: 주간 ▶ KD/월예상 빠른 납기 (R-5). 실리콘 1차 한정 → 재료 구분 필드 유지.

## 4.7 UX 원칙
베테랑 친화 (큰 글씨·단순 메뉴), 자동 vs 수동 시각 구분, 본인 공정만 필터(RBAC), 데스크탑+태블릿 반응형, 결과 근거 항상 표시(블랙박스 X).

## 4.8 신뢰성·가용성
단일 서버 + 일일 백업. 시스템 다운 시 수기 절차 (엑셀 export 백업). 정기 점검 월 1회.

# 6. ★ Differential Value (10x 가치 근거)

본 시스템의 대안(현 운영) 대비 가치를 **속도·정확·확장·데이터·비용** 5개 차원에서 정량화. **모든 차원에서 10배 이상 또는 새로운 가치 창출**.

## 6.1 Speed (속도) — **약 48배 개선**

| 활동 | 현재 | 도입 후 | 배수 |
|---|---|---|---|
| 수주 변동 영향 파악 | 4시간 | **5분** | **48배** |
| 슬롯 배치 결정 (성형) | 0.5~1시간 | **5초 + 검토 5분** | **6~12배** |
| 분기 보고서 작성 | 며칠 | **30분** | **수십 배** |
| 통합 시간 (영업) | 주 4시간 | 주 1.5시간 | 2.7배 |
| 자원 이상 재계획 | 1~2시간 | **5분** | **12~24배** |

**대표 지표: 4시간 → 5분 = 약 50배 (10배 기준 확실히 충족)**

## 6.2 Accuracy (정확도) — **사람의 한계 돌파**

| 항목 | 현재 | 도입 후 | 가치 |
|---|---|---|---|
| 슬롯 위치 제약 계산 | **한 번에 불가** (사람 한계) | **5초 자동 초안** | 사람의 인지 한계 돌파 |
| E그룹 묶음 최적화 | 시간 부족으로 포기 | 자동 최적 묶음 | 미실시 → 100% 실시 |
| 변동 영향 추적 | 일일이 확인 (누락 위험) | 자동 식별 (누락 0) | 누락률 대폭 감소 |
| 납기 준수율 | 93% | ≥ 99% | **사고 7% → 1% (-86%)** |

**대표 지표: 한 번에 계산 불가능했던 작업이 5초만에 가능 = 무한 배 (사람의 한계 돌파)**

## 6.3 Scalability (확장성) — **N배 확대 가능**

| 차원 | 현재 한계 | 도입 후 |
|---|---|---|
| 재료 종류 | 실리콘 1종 (수기 한계) | EPDM·NBR 등 N종 (마스터만 추가) |
| 공장 수 | 본사 1개 | 다공장 (사내망 또는 클라우드 이전) |
| 사용자 | 20명 | 더 큰 조직 (RBAC·인증 인프라 보유) |
| SaaS化 옵션 | 불가 | 미래 옵션 (Cloud-Ready) |

**대표 지표: 1 재료 → N 재료, 1 공장 → N 공장 = 무한 확장 가능 가치**

## 6.4 Data Asset (데이터 자산) — **0% → 100% (없던 자산 신규 창출)**

| 자산 | 현재 | 도입 후 |
|---|---|---|
| 단일 통합 DB | **0%** | **100%** (KSF-5) |
| Audit 로그 | 부재 | 5년 보존 (자동차부품 추적성) |
| 베테랑 노하우 명문화 | 머리에만 | 마스터 데이터 + 변경 이력 |
| KSF 시계열 데이터 | 없음 | 분 단위 누적 |
| 데이터 기반 의사결정 | 감 의존 | 정량 |

**대표 지표: 데이터 자산 0% → 100% = "없던 자산을 새로 창출" = 무한 배**

## 6.5 Cost (비용) — **연간 정규직 0.5명 분량 + 손실 감소**

| 항목 | 현재 | 도입 후 | 차이 |
|---|---|---|---|
| 스케줄링 시간 | 주 24시간 | 주 12시간 | **연 ≈ 1,000시간** (정규직 0.5명) |
| 다이/노즐+금형 변경 | 일 5~10회 | -30% | 라인 비가동 **월 55→38h** |
| 납기 페널티 | 7% 사고율 | 1% 목표 | **-86%** |

**대표 지표: 연간 1,000시간 인건비 절감만으로 회수 18개월 이내**

## 6.6 종합 — 5개 차원 모두 10배 이상

| 차원 | 배수 | 결론 |
|---|---|---|
| 속도 | **48배** | ✅ 10배 이상 |

→ **5/5 차원 모두 10배 이상 가치** = Differential Value 명확히 입증.
