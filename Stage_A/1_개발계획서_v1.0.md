## 1. 프로젝트 개요

### 1.1 프로젝트명
사내 생산 스케줄링 시스템 (Production Scheduling System, 이하 "본 시스템")

### 1.2 목적
자동차부품 고무호스 제조 공정의 **수주 통합 → 성형·압출 스케줄링 → MES 연동**을 자동화하여, 납기 준수율을 높이고 공정 손실(금형 교체·색상 전환)을 최소화한다.

### 1.3 도입 배경
- 수주 데이터가 **월별 예상 / KD / 주간 발주** 등 엑셀별로 파편화되어 있어 통합 관리 불가
- 자동차부품 특성상 **다품종·다품번** 구조로 수기 스케줄링 한계
- 성형·압출 공정은 **제약변수가 많아** 사람의 경험에만 의존 시 손실 발생
- 자체 MES 작업실적과의 연동이 부재하여 계획-실적 괴리 발생

### 1.4 도입 가치 (요약)
| 영역 | 기대효과 |
|---|---|
| 납기 | 백워드 스케줄링으로 D-2/D-1 룰 자동 보장 |
| 비용 | 금형 교체·색상 전환 횟수 최소화 |
| 의사결정 | 수주 변경 시 영향 시뮬레이션 가능 |
| 데이터 | 엑셀 파편화 해소, 단일 통합 DB 확보 |

## 2. 사업 환경 및 문제 인식

### 2.1 사업 환경
- **업종**: 자동차부품 제조 (고무호스)
- **고객**: 자동차 OEM/Tier 공급 (B2B 수주 기반)
- **공정**: 압출(관체 생산) → 성형(가류) → 검사 → 출하

### 2.2 사내 Value Chain 상의 위치
```
[영업·수주]──[자재구매]──[압출]──[성형]──[검사]──[출하]──[사후관리]
     ▲           ▲          ▲       ▲
     │           │          │       │
     └───────────┴──────────┴───────┘
              본 시스템의 영향 구간
              (수주 통합 + 압출/성형 스케줄링 + 실적 연동)
```

### 2.3 문제 정의 (As-Is → To-Be)

| 영역 | As-Is (현재) | To-Be (도입 후) |
|---|---|---|
| 수주 데이터 | 월예상/KD/주간발주 엑셀 3종 파편화 | 단일 통합 DB, 차이 검증 자동화 |
| 스케줄링 | 수기 작성, 경험 의존 | 룰베이스 자동 + 수동 보정, 점진적 최적화 |
| 제약변수 | 머릿속에만 존재 | 명문화·시스템화 |
| 실적 연동 | MES 별도 운영, 수기 대조 | 자동 연동, 진척률 실시간 모니터링 |
| 변경 대응 | 수주 변동 시 며칠 소요 | 5분 이내 영향 파악 |

> 상세 문제정의서는 Phase A의 산출물로 별도 작성한다.

## 3. 서비스 스코프 및 핵심 비즈니스 룰

### 3.1 1차 도입 범위 (P0 — MVP)

| # | 모듈 | 핵심 기능 |
|---|---|---|
| 1 | 제품 수주 정보 통합 | 엑셀 업로드, 매핑, 통합 DB, 차이 분석 |
| 2 | 성형 공정 스케줄링 | 주간 단위, 제약변수 반영, 간트차트 |
| 3 | 압출 공정 스케줄링 | 성형 의존, 색상/다이 최적화 |

### 3.2 후속 단계 (P1 / P2)
- **P1**: MES 양방향 연동 (실적 자동수집, 작업지시 송신), 모바일 반응형 조회
- **P2**: 자동 최적화 엔진 (Google OR-Tools / CP-SAT 솔버), KPI 대시보드

### 3.3 핵심 비즈니스 룰 — **백워드 스케줄링 모델**

```
                                 ↓ 시간 흐름 →
[압출 시작]──[압출 완료]──[성형 시작]──[성형 완료]──[검사/포장]──[납품]
              D-3 까지        D-3        D-2 까지                  D
              (=성형 투입       │           │                       │
               1일 전)          └─1일 이상──┘                       │
                                            └─────2일 버퍼──────────┘
```

| 룰 | 정의 | 성격 |
|---|---|---|
| R-1 | 성형 공정은 납품예정일 **D-2까지** 완료 | 하드 제약 |
| R-2 | 압출 공정은 성형 투입일 **D-1까지** 완료 | 하드 제약 |
| R-3 | 모든 스케줄러는 납품일을 고정점으로 한 backward scheduling으로 설계 | 설계 원칙 |

### 3.4 범위 제외 (Out of Scope)
- 검사·포장·출하 공정 스케줄링 (P2 이후 검토)
- 자재 자동 발주 (ERP 영역)
- 원가계산 (ERP 영역)
- 외부망 노출 (사내망 전용)

### 6.2 모듈 2 — 성형 공정 스케줄링

#### 입력

- 품번 마스터 (금형, 사이클타임, 캐비티 수)
- 제약변수
- MES 재공품 현황
- 라인 가동 캘린더

#### 제약변수 카탈로그

| 분류 | 변수 |
|---|---|
| 장비 | 성형기 대수 / 가용 시간 (교대 포함) |
| 금형 | 가능 품번, 금형 수량, 교체시간, 동시 가동 캐비티 |
| 품질 | 가류온도/시간 (사이클타임) |
| 인력 | 작업자 스킬, 교대 인원 |
| 자재 | 압출 관체 공급 시점 (모듈 3 의존) |
| 납기 | D-2 완료 deadline (하드 제약) |
| 운영 | 동일금형 연속생산 최소수량, 우선순위 고객 |

> 상세 변수와 정량값은 Phase A에서 현장 인터뷰 후 확정.

#### 알고리즘
- **1단계 (P0)**: 룰베이스 + 수동 보정
- **2단계 (P2)**: OR-Tools / CP-SAT 솔버 도입

#### 출력
- 주간 성형 스케줄 (간트차트 + 표)
- 모듈 3에 대한 관체 요청서 자동 생성

### 6.3 모듈 3 — 압출 공정 스케줄링

#### 입력
- 모듈 2의 관체 소요 일정
- 압출 제약변수
- MES 압출기 가동 현황

#### 제약변수 카탈로그

| 분류 | 변수 |
|---|---|
| 장비 | 압출기 대수, 헤드 종류 |
| 다이 | 가능 호스규격, 다이 교체시간 |
| 재료 | 컴파운드 종류, **색상 교체시간** (전환방향별 상이) |
| 품질 | 워밍업 시간, 안정화 폐기량 |
| 운영 | 동일다이/색상 연속생산 최소수량 |
| 납기 | 성형 투입 D-1 완료 (하드 제약) |

#### 핵심 최적화 — 색상/다이 전환 최소화
- TSP 유사 알고리즘으로 같은 색상·다이끼리 묶음
- D-1 deadline을 위반하지 않는 범위 내에서만 묶음 허용

#### 알고리즘 흐름
```
1. 모듈 2의 관체 요청을 deadline 기준 buckets에 분배
2. 각 bucket 내에서 색상/다이 전환비용 최소화 순서 결정
3. 압출기에 배정 (다이 호환성 + 가동시간 고려)
4. 출력: 주간 압출 스케줄 + 컴파운드 소요량
```

## 7. 외부 시스템 연동 (ERP·MES)

### 7.1 자체 MES (양방향)
- API/DB 직접 정의 가능 → 인터페이스 자유 설계
- **읽기**: 작업실적, 라인상태, 재공품 (5분 폴링 또는 webhook)
- **쓰기**: 확정된 작업지시 (현장 태블릿/모니터에 표출)
- 인증: 사내망이므로 API key 또는 IP 화이트리스트

### 7.2 영림원 ERP (단방향, 마스터 동기화)
- **선결 확인사항**:
  1. 표준 API/Web Service 명세서 수령
  2. 직접 DB 조회 가능 여부 (라이선스·지원 계약)
  3. SELECT 전용 DB 계정 발급 가능 여부
- **연동 항목**: 품번마스터, BOM, 거래처, 표준원가
- **갱신 주기**: 1일 1회 야간 배치
- 수주 데이터는 ERP 미경유 (엑셀에서 직접)

### 7.3 통합 데이터 흐름
```
                    [영림원 ERP]
                         │ (1일 1회 야간)
                         ▼
[엑셀 수주]──→ [본 시스템 통합 DB] ←──── [자체 MES]
                         │                  ▲ │
                ┌────────┼────────┐         │ │
                ▼        ▼        ▼         │ │
            [수주통합][성형스케줄][압출스케줄] │ │
                                  │         │ │
                                  └─작업지시─┘ │
                                       작업실적─┘
```

| 페르소나 + CJM | 🔄 변형 | 사내 사용자 + 업무여정맵 |
| JTBD | ✅ 유지 | |
| VPS | 🔄 변형 | 도입 정당화서로 |
| RPD/PRD | ✅ 유지 | |
| SRS | ✅ 유지 (PRD와 통합) | |
| 상세 Task | ✅ 유지 | |
| 프로토타이핑 | 🔄 축소 | 와이어프레임 + 단계별 MVP로 대체 |

### 8.2 Phase별 상세

#### Phase A. 진단·정의 (1~2주)
| 산출물 | 내용 |
|---|---|
| 사내 Value Chain 분석 | 자사 가치사슬 + 본 시스템 영향구간 (1장) |
| KSF 카드 | 5~7개 (지표·현재·목표·측정방법) |
| **문제정의서 v1** | As-Is / Pain Point / 정량손실 / To-Be / Gap (5~10p) |

→ Value Chain·KSF는 문제정의서 안에 통합 가능

#### Phase B. 사용자·가치 정의 (1주, 단축)
| 산출물 | 내용 |
|---|---|
| 페르소나 카드 | 4~5개 (가상 작성 + 이사님 검토) |
| 업무 여정맵 | 페르소나당 1장 (As-Is / To-Be) |
| 현장 인터뷰 (1일) | 성형·압출 반장 각 1명, 30분씩 |
| JTBD 리스트 | "~를 위해 ~를 하고 싶다" 형태 |
| VPS (도입 정당화서) | ROI, 정량·정성 효과, 1p 임원자료 |

#### Phase C. 명세 (3~4주)
| 산출물 | 내용 |
|---|---|
| **통합 요구사항 명세서**<br>(PRD + SRS, 사내 명칭은 PDD) | 기능 요구·비기능 요구·데이터 모델·API·연동 사양 |
| 핵심화면 와이어프레임 | Figma 또는 PPT, 5~10장 (수주통합·성형 간트·압출 간트·실적조회) |

> 풀 프로토타입은 작성하지 않음. 단계별 MVP가 검증 역할 수행.

#### Phase D. 실행 (단계별 MVP)
| Sub-phase | 기간 | 산출물 |
|---|---|---|
| D-1. 수주 통합 | 1~2개월 | 엑셀 import, 통합 대시보드, ERP 마스터 동기화 |
| D-2. 성형 스케줄러 (룰베이스) | 2~3개월 | 간트 UI, 충돌검증, 작업지시 출력 |
| D-3. 압출 스케줄러 + MES 연동 | 1~2개월 | 압출 스케줄, 실적 자동수집 |
| D-4. 자동 최적화 엔진 (P2) | 3개월+ | OR-Tools 기반 자동 일정 생성 |

### 8.3 전체 일정 요약

```
[Phase A] 1~2주  ─── 문제정의서 v1 → 임원 보고·예산 확보
   ▼
[Phase B] 1주    ─── 페르소나·VPS → 현장 검증
   ▼
[Phase C] 3~4주  ─── PDD + 와이어프레임 → 외주 RFP 또는 사내개발 spec
   ▼
[Phase D] 6~8개월 ── 단계별 MVP 출시 (D-1 → D-2 → D-3 → D-4)
```

**기획 단계 총 6~8주, 개발 단계 6~8개월** (P2 제외 시).
