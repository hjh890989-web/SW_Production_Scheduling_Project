## ✅ Task Breakdown
- [ ] `lib/auth.ts` Credentials Provider 본격 구현
- [ ] `bcrypt` 12 rounds로 비밀번호 해시 (`bcrypt.hash`, `bcrypt.compare`)
- [ ] 세션 8h idle timeout (`session.maxAge = 8 * 60 * 60`)
- [ ] User.lastLoginAt 자동 갱신 (callbacks.signIn)
- [ ] AuditLog `action: LOGIN` 자동 기록 (callbacks.events)
- [ ] 환경변수 검증 (`NEXTAUTH_SECRET` 필수)
- [ ] JWT vs Database session 결정 (DB 권장 — Audit 추적 용이)

## 🧪 Acceptance Criteria
### AC T1.1-1 (정상)
- **Given**: 등록된 사용자 ID/PW
- **When**: 로그인 시도
- **Then**: 세션 생성, AuditLog INSERT, 응답 ≤ 1초

### AC T1.1-2 (정상)
- **Given**: 비밀번호 평문 "test1234"
- **When**: 사용자 등록
- **Then**: DB에는 bcrypt 해시 저장 (평문 절대 금지)

### 🔥 AC T1.1-F1 (실패 — 잘못된 비밀번호)
- **Given**: 잘못된 PW
- **When**: 로그인 시도
- **Then**: 401 + 카운터 +1, AuditLog `action: LOGIN_FAILED` 기록

## ⚙️ Constraints
- **bcrypt 12 rounds**: 100ms 이내 해시 (성능 vs 보안 균형)
- **세션 저장**: DB Session 테이블
- **사용 금지**: 평문 비밀번호 저장, JWT secret 코드 하드코딩
