# Sprint 5 베타 사용성 테스트 플랜 (T5.12)

> J-MR-2(수동 보정 권한)는 **도입 성패를 가르는 핵심 가설**이다. 본 플랜은 성형 반장 페르소나(박철수)를 대상으로 W-4 성형 스케줄·드래그 재배분의 사용성을 검증한다.
> 자동화 루프 환경에서는 실사용자 세션을 진행할 수 없으므로, 본 문서(테스트 플랜)와 인앱 피드백 수집(`/feedback`, Notification `BETA_FEEDBACK`)으로 갈음한다.

## 1. 대상·환경
- **대상**: 성형 반장(MOLDING_LEADER, 시드 계정 `parkcs`), 생산관리(`kimms`).
- **디바이스**: 태블릿(가로/세로) + 데스크톱. 텍스트 ≥16px, 터치 ≥44px(T5.10) 확인.
- **데이터**: `npx prisma db seed` + 수주 엑셀 업로드(W-2)로 ACTIVE 수주 확보 후 자동 생성.

## 2. 시나리오 & 성공 기준
| # | 시나리오 | 단계 | 성공 기준 |
|---|---|---|---|
| S1 | 자동 스케줄 생성 | 로그인 → /molding → "자동 스케줄 생성" | ≤5초 초안, 슬롯 X 배치 0건(T5.2), 회색(AUTO) 셀 표시 |
| S2 | 드래그 재배분(J-MR-2) | AUTO 셀을 다른 가류기·일자로 드래그 | 차단 없이 이동, AUTO→MANUAL(파랑 테두리), ≤500ms |
| S3 | 위치 X 배치 | 허용되지 않은 슬롯으로 드래그 | **빨간 경고만**, 배치는 허용, audit `rule_violation=true` |
| S4 | 동시 편집 | 두 사용자가 같은 셀 변경 | 두 번째 저장 시 "방금 변경됨 — 새로고침" 충돌 안내 |
| S5 | 근거 확인 | 셀 hover | 품번·회전수·근거 툴팁(T5.9) |

## 3. 측정 지표(KSF-6 채택률 선행)
- 자동 결과 대비 **수동 보정 비율**(MANUAL/(AUTO+MANUAL)) — 너무 높으면 자동 품질 개선 필요.
- 위치 위반 발생/해소 건수.
- 만족도(1~5) 평균 ≥ 4 목표(드래그 직관성·경고 명확성).

## 4. 피드백 수집
- 인앱 `/feedback` 폼(시나리오·만족도·의견) → Notification(type `BETA_FEEDBACK`, admin 대상) + AuditLog `BETA_FEEDBACK_SUBMITTED`.
- 회수 후 본 문서 §5에 요약·조치 항목 기록(후속 스프린트 반영).
